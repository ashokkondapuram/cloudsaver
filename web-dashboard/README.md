# CloudSaver web dashboard

Next.js 15 App Router, React 19, TypeScript and Tailwind CSS frontend. The inventory uses TanStack Table for filtering/sorting and TanStack Virtual for row rendering at 10,000+ rows. The local `components/ui/button.tsx` is an owned shadcn-style primitive; there is no external design-service dependency.

## Run locally

Use Node.js 22 and start the API gateway first using the main project README. Then:

```bash
cd web-dashboard
npm ci
API_GATEWAY_URL=http://127.0.0.1:8000 npm run dev
```

Open `http://127.0.0.1:3000`. Enter the workspace access key generated during backend setup. It is retained in React memory only; reloading the page clears it. Use localhost for development and HTTPS for any hosted environment.

The browser calls same-origin `/api/v1/*` endpoints. A narrowly scoped Next route handler forwards these calls to the operator-configured `API_GATEWAY_URL`. The API key is forwarded in the Authorization header, not a URL. The gateway URL is a server-side runtime setting and is not baked into frontend JS.

## Production build

```bash
npm run typecheck
npm run build
API_GATEWAY_URL=http://127.0.0.1:8000 npm start
```

The supplied Dockerfile builds with Node.js 22 and starts the standalone server as the `node` user on port 3000. Set `API_GATEWAY_URL=http://api-gateway:8000` in the container runtime, as the root compose file does. The Docker build excludes host dependencies, build output and environment files.

## Supported workflow

- Connect with a pre-provisioned workspace access key.
- Run an Azure scan or a clearly labeled demo fixture scan, depending on backend mode.
- View saved scan history and select a prior scan.
- Search, filter by rule/severity, sort columns and inspect resource evidence.
- Export the selected complete scan as JSON or CSV. CSV neutralizes spreadsheet formula prefixes.
- For supported live disk/IP findings, download a remediation review script generated by the API. Downloading does not execute it. This control is hidden for demo scans.

Live dollar values are shown as “Not estimated” until the backend has supported billing estimates. No synthetic spend trends or savings claims are shown. There is no Gemini integration in this application.

## Current boundaries

The engineering MVP uses manually provisioned workspace keys rather than a browser Entra OAuth/SSO flow. The web app does not provide billing, scheduled scans or notification preferences. See the root roadmap for production release work. Visual QA in a real browser and external Azure credentials are required before any production launch.
