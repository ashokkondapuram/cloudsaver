## Preserved safety boundaries

- Entra signatures, issuer/audience/lifetime/scope/role checks; provider/scope narrowing and authoritative identity outage failure.
- Fixed service destinations, request correlation, bounded JSON and fail-closed Redis limiting.
- PostgreSQL forced RLS, transaction-local tenant context, bounded pools and connection reset.
- Human TenantAdmin approval, immutable plan/destination hashes, single-use permits, lease fencing and reconciliation for uncertain writes.
- No arbitrary model-generated TypeScript execution. Only the reviewed bounded connector program runs.
- No data harvesting into a client-trained knowledge base. Configured repository exports remain explicit review actions.
- No automatic resource resizing, deletion, Terraform apply or claim that a draft PR establishes deployed parity or realized savings.

## Evidence and release decisions

The first regression run reproduced six baseline failures: five gateway workflows and a billing summary GET that attempted ingestion. Their fixes and later full-suite results must be assessed alongside the linked tests and CI logs for the exact release SHA. At 1.5.1 the aggregate coverage gate covered `auth`, `agent_contract`, `agent_store`, `provider_access`, `billing_jobs` and `finops_api`. Version 1.6.0 adds the four outcome modules listed in its runbook. The aggregate threshold is not a claim of 85% coverage of every route or each module separately.

The Gitleaks gate scans tracked release source files, excluding its self-referential manifest. Four fixed public synthetic test constants have line-specific allow comments; unknown new secrets remain blocked and a generated synthetic credential is a negative control. This is not a Git-history secret audit.

Mock provider and mocked credential tests verify contracts without live cloud effects. The real-stack runner uses synthetic local development credentials to test transport through actual processes; GitHub publishing and AI inference remain disabled. It does not prove production Entra, IAM, financial reconciliation or HA operation.

Do not change the release decision to GO until named Security, Engineering, SRE, FinOps, Product and Privacy/business reviewers sign immutable evidence for every enabled launch feature. Features without accepted gates stay disabled or outside the supported scope.

Repository administration was rechecked on 2026-10-25 before publication: the branch API reported `main.protected=false` and the visible ruleset list was empty. The connected GitHub tools provide no administration write capability. Required-check and human-review enforcement therefore remains an explicit repository-owner launch gate; adding workflow YAML does not close it.
