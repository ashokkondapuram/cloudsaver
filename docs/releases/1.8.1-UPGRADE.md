# CloudSaver 1.8.1 — deployment contracts and engineering policy patch

This is the current release runbook. Schema head is unchanged from [1.8.0](1.8.0-UPGRADE.md): core Alembic **`0033_platform_outbox_lease`**, identity **`i0013_multicloud_analysis_catalog`**. No new migrations are required to move from 1.8.0 to 1.8.1.

## What changed in 1.8.1

- **Deployment environment reference:** [DEPLOYMENT_ENVIRONMENT.md](../DEPLOYMENT_ENVIRONMENT.md) documents secret, structural, and tunable variables across Docker Compose, Azure Container Apps, and Helm.
- **Engineering actions:** All engineering resize/restore paths default to **`zero_downtime`** policy and agent plans carry `resize_mode: zero_downtime`.
- **FinOps / agent routing:** Catalog rule IDs map to the correct workflow channel (FinOps autopilot, engineering plan, K8 patch, remediation, manual).
- **External deployment repos:** [cloudsaver-containerapps](https://github.com/ashokkondapuram/cloudsaver-containerapps) and [cloudsaver-helm](https://github.com/ashokkondapuram/cloudsaver-helm) align Bicep/Helm env with 1.8.1 image tags and optional `CLOUDSAVER_ENGINEERING_CURSOR_KEY` bindings.

## Upgrade and deployment

1. Back up core and identity databases under your approved recovery policy.
2. Deploy one matching artifact/image set at tag **`1.8.1`** (or an immutable digest built from this release commit).
3. If already on 1.8.0 with migration `0033` applied, skip migration steps unless your manifest check fails.
4. Rebuild or pull **`cloudsaver-python:1.8.1`** for Compose and `scripts/start_stack.py`.
5. Refresh ACA `production.json` / Helm `values.yaml` image tags and `application.sourceRevision` per [DEPLOYMENT_ENVIRONMENT.md](../DEPLOYMENT_ENVIRONMENT.md).
