## Development upgrade

Back up the core and identity databases and preserve the key/pepper material under your recovery policy. Use matching release images for the API, gateway, workers and UIs. Never delete customer volumes to repair a migration or password mismatch.

```sh
docker compose --env-file .env up --build migrate
docker compose --env-file .env up -d --build
```

Existing tenant history and credentials remain in place. The new `billing-sync-worker` starts in normal Compose; no browser/API request runs a provider billing query. If running outside Compose, supervise `python -m workers.billing_sync` beside the core API. The periodic scheduler only queues jobs; the polling worker consumes them directly from PostgreSQL, avoiding a DB-to-broker publication gap.

Verify `/readyz` for serving traffic and `/healthz` only for process liveness. Gateway readiness includes core readiness. Production also requires a fresh authoritative directory projection. Before allowing customer traffic, verify actual tenant reads, role restrictions, financial evidence, job recovery and the saved-data migration graph against the release artifact.

## Production profile

Supply secrets through the approved platform secret mechanism. These non-secret switches are necessary but do not establish a complete HA production deployment:

```dotenv
CLOUDSAVER_ENVIRONMENT=production
CLOUDSAVER_TENANT_REGISTRY=database
CLOUDSAVER_DIRECTORY_MODE=cutover
CLOUDSAVER_KEY_VERIFIER=identity
CLOUDSAVER_CLOUD_IDENTITY=managed_identity
CLOUDSAVER_INSTALL_AZURE_CLI=false
CLOUDSAVER_AGENT_AZURE_IDENTITY=managed_identity
CLOUDSAVER_DIRECTORY_MAX_LAG_SECONDS=30
```

Use a restricted PostgreSQL runtime role, the reviewed core/identity service identities, and authoritative identity-service configuration. Production refuses SQLite, local/shadow key decisions, registry fallback, developer cloud credentials and developer CLI images. Identity outage never enables a legacy key fallback.

Workspace-key mode uses authoritative identity verification, including scoped roles, revocation and suspension. Optional Entra mode additionally requires `CLOUDSAVER_AUTH_MODE=entra`, a nonempty `CLOUDSAVER_ENTRA_AUDIENCE` and explicit `CLOUDSAVER_ENTRA_ACCESS_POLICY=tenant_roles`. That policy maps a verified Entra tenant to an active provisioned workspace and grants its assigned application roles across that workspace; it does **not** invent per-user provider/scope restrictions or customer membership bindings. Security must approve this distinct access model before enabling it. Both modes enforce the product suspension policy; verified-human TenantAdmin is still mandatory for agent approval.

The shared directory cursor/freshness is database-backed. Every projector competes for one transaction lock; all updates and cursor advancement commit together. A failed projector rolls back, another can acquire the lock, and cursors cannot regress. Production denies authenticated access and serving readiness if the shared freshness is absent or older than the configured 5–300-second bound. A successful empty feed poll refreshes the shared heartbeat. This source behavior still needs multi-replica production acceptance.

Compose remains development orchestration. Required production work includes TLS ingress/trusted-proxy validation, private database/broker paths, reviewed identity egress, managed secrets, least privilege, immutable image digests, redundancy, backups/PITR, measured capacity, monitoring and recovery drills. Do not expose development defaults as an accepted enterprise architecture.

## Billing jobs and recovery

`POST /api/v1/finops/sync?currency=USD` requires finance authorization and JSON `{"idempotency_key":"UUID"}`. It returns **202**, `Location`, `Retry-After` and a durable `poll_url`. Repeating the same key/currency returns the original job. Reusing it for a different currency or submitting another request while a workspace job is active returns **409**. GET summary and GET status have no provider/write side effects.

Poll `GET /api/v1/finops/sync-jobs/{id}`. `POST .../{id}/cancel` stops queued work or prevents the next uncommitted scope; already committed charges remain. Jobs are tenant-owned with forced RLS. IDs, status and timestamps are audit references, not authorization. Foreign jobs return 404. The dashboard remembers only its job reference/idempotency key per workspace/currency and resumes polling after reload; it never stores a cloud credential for this workflow.

Execution bounds:

- One active job per workspace, at most eight configured authorized scopes per job.
- One elected polling worker per core database; one provider scope at a time. A transient leader-connection loss can leave one already-started read in flight; scope lease/token checks fence commits. Supervise/restart the worker on failure.
- Ten-minute scope lease; a claimed scope can be recovered after process loss. Provider calls are read-only, bounded by their adapters. Jobs older than six hours cannot start another scope.
- Up to 5,000 rows per source response, ten AWS pages, explicit BigQuery query budget and at most sixteen observed currencies per scheduled scope.
- Financial import deltas and the per-scope checkpoint commit in one transaction under the job lease. A crash before commit rolls back both; after commit the checkpoint prevents another import. Lease loss refuses a stale worker's commit.
- Current scope/connector authorization is rechecked after the read. A revoked scope cannot commit new charges. Provider errors expose safe codes and the job correlation ID.

Provider reads can incur provider query costs; these bounds are engineering limits, not an approved customer spend budget or tested throughput SLA. Monitor oldest queued age, failures, unresolved differences and worker supervision. A dead worker must be detected by the serving platform's accepted monitoring system; a responsive API alone does not prove job progress.

## Provider evidence boundaries

| Provider | Source and granularity | Window and bounds | Reconciliation / absent data |
| --- | --- | --- | --- |
| Azure | Cost Management ActualCost; resource/day | Thirty-day UTC interval `[today-32 days, today-2 days)`; paginated responses are rejected | Amortization and completeness unverified; absent groups unresolved |
| AWS | Cost Explorer linked-account/day/record-type; UnblendedCost + AmortizedCost | Same explicit interval; at most ten pages; no SDK automatic retries | No resource IDs or CUR proof; completeness unverified |
| GCP | Standard BigQuery billing export; project/day/type; cost and export credits | Same explicit interval; parameterized scope/window; 1 GB query budget; incomplete/paged jobs rejected | No inferred resource attribution; completeness unverified |

Scheduled jobs keep currencies separate. The view's selected billing period may differ from this connector interval; days outside imported evidence stay missing and must not become zero. Existing preceding-day resource-cost columns retain their own attribution window; account/project totals are not spread over resources. Do not promise these adapters as complete large-tenant billing until paging/export/reconciliation acceptance is measured.

Snapshots retain immutable deltas. For incomplete snapshots, disappeared or reclassified previous groups are surfaced in `unresolved_absent_groups`; amounts are not silently reversed. The internal authoritative-snapshot path requires a source watermark and reconciles the union of prior/new groups, including a complete empty snapshot. **Current readers do not assert that authority.** The internal mechanism is a tested extension point, not certification of provider completeness. Retail opportunity, actual billed amounts, modeled commitments and verified realized savings remain distinct.

## Identity egress

In platform Compose, identity-service remains on internal networks. Its HTTPS proxy is `identity-egress:3128`, which alone has a non-internal egress network. The default exact approved destination is `login.microsoftonline.com:443`. CONNECT denies all other authorities, non-443 ports, IP literals and DNS results containing private/non-global addresses. TLS passes through without decryption or payload logging.

For an approved Key Vault or other identity secret integration, explicitly add its exact DNS name to `PLATFORM_IDENTITY_EGRESS_HOSTS` after reviewing data residency, credentials and destination ownership. Wildcards are not accepted. This proxy is public-endpoint-only: a Key Vault private endpoint requires a separately reviewed private network path and remains an unaccepted integration until tested. Do not attach the identity database or Redis to an external network. Validate cold-cache keys, rollover, DNS/proxy outages and remote secret retrieval on the real production network. A source allowlist test is not a deployed egress verification.

## Verification and release controls

CI retains pinned Actions and no checkout credential persistence. It now checks core, isolated platform Python, worker, portal, dashboard, real-stack HTTP paths, high severity SAST, dependency audits, a pinned secret scanner with negative control, SBOM generation and the release inventory. The aggregate `required-verification` job fails if any required package/check fails; configure repository rulesets/branch protection to require it and human review. Workflow source does not prove repository administration is enforced.

The worker pins Azure Identity 4.14.0 and overrides resolved MSAL Node to patched 7.1.1 for GHSA-xcx6-jx8p-x3h5. Managed-identity and workload-assertion SDK compatibility tests use mocked transports; actual tenant/workload IAM validation remains required. No interactive authorization-code flow is exposed by the worker. No vulnerability exception is silently accepted.

The dashboard has per-response script CSP nonces, frame denial and no-store HTML. Existing component inline styles remain allowed. The portal retains its separate session/CSRF protections; payment parsing now rejects unsafe-integer precision loss. Complete production session, TLS, accessibility and independent security reviews remain launch gates.

Neither this runbook nor passing tests establish compliance certification, independent penetration testing, RPO/RTO achievement, invoice accuracy, HA service targets or customer contractual acceptance. See the companion gate ledger for what remains open.
