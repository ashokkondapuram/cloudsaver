## What changed in 1.8.0

- **Resource pipeline:** Durable finding evidence, scoped coverage manifests, billable-resource catalog defaults (`cost_scope=billable`).
- **Drift path:** Bounded cloud-event ingress (max 100 events per request), fenced `platform_outbox_intents` leases (migration **`0033_platform_outbox_lease`**), Redis contention releases DB claims.
- **Provider parsing:** Non-finite JSON numbers rejected in `read_json`; telemetry integers bounded in `evaluate_series`.
- **Azure collection:** Public ARM endpoint profile shared across requests and pagination continuation checks.

## Upgrade and deployment

1. Back up core and identity databases under your approved recovery policy.
2. Deploy one matching artifact/image set. Core Alembic head is **`0033_platform_outbox_lease`** (after `0032_v3_semantic_embeddings`). Identity head remains **`i0013_multicloud_analysis_catalog`**.
3. Apply migrations before workers:

   ```sh
   docker compose --env-file .env up --build migrate
   docker compose --env-file .env up -d --build
   ```

4. Rebuild the Python image tag **`cloudsaver-python:1.8.0`** (Compose and `scripts/start_stack.py` reference this label).
5. Enable drift outbox dispatch only after Redis and migration `0033` are confirmed: `CLOUDSAVER_PLATFORM_OUTBOX_DISPATCH=true`.

## Rollback

Downgrade refuses when new outbox lease columns or drift rows exist. Do not delete customer volumes to repair a failed upgrade. Recovery requires a reviewed restore procedure coordinated with outstanding leased outbox intents.
